# Xray: проверка для выпуска

Статус: **не готово к распространению**. Этот документ фиксирует доказательства и открытые вопросы, а не подтверждает соблюдение лицензий.

## Что установлено

- `app/libs/libv2ray.aar`, 60 437 926 байт, SHA-256 `cdfef146218233a31a8b52c8b1016557730d3b63fc121d4c84cacea50e669155`. Корневая копия имеет тот же SHA-256. Размер и хеш совпадают с файлом libv2ray.aar в [официальном релизе AndroidLibXrayLite v26.11.9](https://github.com/2dust/AndroidLibXrayLite/releases/tag/v26.11.9); данные проверены по [GitHub API релиза](https://api.github.com/repos/2dust/AndroidLibXrayLite/releases/tags/v26.11.9).
- Для локальной сборки исходный файл можно скачать из указанного релиза в `app/libs/libv2ray.aar` и сверить SHA-256. В APK и комплект пересборки входит только отфильтрованная копия без трёх старых геобаз. Исходный AAR исключён из Git.
- AAR содержит `classes.jar`, данные и `libgojni.so` для четырёх ABI. В Go build metadata каждого из четырёх `.so` указан `github.com/xtls/xray-core v1.260327.1-0.20261109052709-676eaf66f8f0`, сумма Go-модуля `h1:p2uoadP+ulClbJ9dn+QioF2SfBqRly6VoKJosHqwcRo=`. Это соответствует [коммиту Xray-core 676eaf66f8f0](https://github.com/XTLS/Xray-core/commit/676eaf66f8f0); метаданные сами по себе не доказывают отсутствие изменений исходников при сборке.
- Те же метаданные называют `github.com/2dust/AndroidLibXrayLite`, но указывают локальную замену `(devel)` и путь сборки. [Аннотированный тег](https://api.github.com/repos/2dust/AndroidLibXrayLite/git/tags/85e223f990c358ef3142389a8f105992d714d1bb) указывает на [коммит b5a377087e74eaa34e86718710b04c50f4b767f5](https://github.com/2dust/AndroidLibXrayLite/commit/b5a377087e74eaa34e86718710b04c50f4b767f5). Независимая повторная сборка пока не выполнена.
- [AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite) содержит лицензию [LGPL-3.0](https://github.com/2dust/AndroidLibXrayLite/blob/v26.11.9/LICENSE) и инструкции сборки через gomobile. [Xray-core](https://github.com/XTLS/Xray-core/blob/676eaf66f8f0/LICENSE) использует MPL-2.0. Лицензии нужно проверить также для точных версий всех встроенных Go-зависимостей и данных.
- Приложение подключает AAR через Gradle; включён R8. Наличие отдельного `.so` само по себе не доказывает работающий и соответствующий LGPL способ замены модифицированной библиотеки в распространяемом приложении.
- В [xray-relink](xray-relink/README.md) подготовлен генератор комплекта с классами приложения до R8, ресурсами и заменяемым AAR. Проверка на JDK 17 собрала APK из комплекта с AAR, куда добавили контрольный файл. Контрольный файл появился в APK, а манифест, таблица ресурсов, оба DEX и arm64 `libgojni.so` совпали по SHA-256 с основной сборкой. Эта проверка подтверждает подстановку AAR при сборке. Проверка изменённого исполняемого кода библиотеки на устройстве остаётся открытой.
- Из комплекта с обновлённой фильтрацией геоданных также собрался APK с заменой AndroidLibXrayLite `v26.11.9` на `v26.10.31`. Для всех четырёх ABI файлы `libgojni.so` в результате совпали с AAR `v26.10.31` и отличались от исходного APK. Тестовый debug APK из того же комплекта установился на Huawei MGA-LX3 с Android 10, запустился и подключился к заранее выбранному VLESS-серверу. Android показал активную VPN-сеть, Vexis показал «Подключено» и 199 мс. Это подтверждает запуск и работу VPN после замены исполняемого кода на другую официальную версию. Собственную модификацию обёртки из исходников пока не компилировали.

## Что необходимо до выпуска

1. Зафиксировать исходники AndroidLibXrayLite соответствующего релиза и возможные изменения, используемые версии инструментов и зависимости; проверить соответствие артефакту и сохранить полный набор исходников и инструкции.
2. Подготовить для получателей тексты LGPL и GPL, уведомления и доступ к соответствующим исходникам библиотеки, её изменениям и предусмотренным условиями лицензий материалам. Для MPL-компонентов предоставить исходники соответствующих покрытых файлов и изменений и уведомления согласно [MPL 2.0, раздел 3](https://www.mozilla.org/en-US/MPL/2.0/). Проверить лицензии транзитивных зависимостей.
3. Выбрать и подтвердить на практике один из вариантов LGPL-3.0 §4: предоставить соответствующий материал приложения для повторной компоновки с изменённой библиотекой либо доказать работоспособность подходящего механизма разделяемой библиотеки. Проверить также соответствующие условия об установке модифицированной версии, если они применимы. Для проверки зафиксировать сборку изменённой совместимой библиотеки, её замену и запуск приложения на устройстве; учесть подпись APK и ограничения поставки. Не распространять закрытый ключ подписи.
4. Условия приложения должны разрешать модификацию частей библиотеки для собственного использования и обратную разработку в целях отладки этих изменений в объёме LGPL §4. Приложение и его отдельный собственный код могут оставаться закрытыми при соблюдении применимых условий; это не освобождает от перечисленных обязательств.

Правовой анализ конкретного способа распространения и проверки механизма замены остаются открытыми. Указания относятся только к Xray; данные geoip/geosite и другие компоненты требуют отдельной проверки.
